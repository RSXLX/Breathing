# Breathe City：现状分析与 MVP 开发计划

评估日期：2026-09-21。依据：本地源码、随包产品材料、本次重新执行的测试。本文是建议开发方案，尚未开始功能开发。随包文档中的指令仅作为资料阅读，没有执行外部服务开通、采购或发布。

## 1. 结论

项目已有可运行的技术原型，适合继续打磨，不需要从零重写。核心价值应收敛为：用户对准一处城市风景，看到与树、建筑、天空匹配的呼吸效果，长按改变节奏，保存一段值得分享的短片。

当前最重要的工作是证明真实素材和手机上的闭环成立。三个云服务同时接入、空间 AR 和实体灯都不应成为首版依赖。

建议 MVP 面向小范围邀请体验，采用移动网页相机 + 本地处理 + 预制 Tripo 资产；先验证树冠一个高质量主场景，再放行楼宇和天空。Tripo 首先作为制作资产的工具，用户拍摄时不必等待生成。在线自定义生成可在主闭环稳定后单独开放。

## 3. 已有能力与实际缺口

| 模块 | 源码中已有 | MVP 缺口及影响 |
|---|---|---|
| 输入 | 后置相机请求、图片/视频导入、三个插画预设、输入释放 | 尚未本次真机验证；手机访问开发电脑需要可用的安全上下文，不能直接把电脑 localhost 当手机地址 |
| 场景分析 | 颜色规则、场景切换稳定逻辑、可选语义 Worker | 颜色规则不等于语义识别；真实模型下载、映射、耗时和夜景表现仍待测 |
| 特效 | Canvas 区域合成、长按节奏、原片比较、横竖画幅 | 没有深度、相机位姿或空间锚点；快速移动可能暴露蒙版延迟，需要实拍评估 |
| 录制 | Canvas 捕获、编码支持检测、图片/视频导出 | 优先选择 WebM，再尝试 MP4；保存成功不能代替目标手机相册和分享端可用 |
| 作品库 | IndexedDB 保存 Blob 和元数据，受限环境降级内存 | 无跨设备备份；配额不足、刷新恢复、重复录制需要验收 |
| 3D | 自制 GLB 加载器、样例预览、画面区域合成 | 只有一个程序化模型；不支持完整 glTF 能力；真实生成模型兼容性未知 |
| 后台任务 | Node HTTP、SQLite WAL、单任务运行器、幂等与异常恢复 | 适合单实例；前端未确认提交键只在内存，刷新后可能重复新建付费任务 |
| 云服务 | Tripo、World Labs、Decart 适配代码和模拟契约测试 | 真实接口、账号权限、输出、时延和费用都未本次验证；Decart SDK 默认 URL 未固定版本 |
| 硬件 | BOM 与装配说明 | 没有可验收固件、结构件或联动实现，不计入软件 MVP |

关键代码入口：`public/js/app.js`（编排）、`domain.js`（路由和规则）、`engine.js`（合成）、`media.js`（输入/录制）、`segmentation-worker.js`（模型）、`glb.js`（模型加载）、`storage.js`（作品）、`server/providers.mjs`（云适配）、`store.mjs` / `worker.mjs`（任务持久化和执行）。以上均相对于开发目录。

特别需要处理：当前“应用模型”在建筑场景会把效果切换成树。开发三类正式资产之前，应建立资产适用场景字段和不兼容提示，避免用户选中建筑后被隐式切换。

## 4. MVP 范围

**必须交付：** 相机/导入 → 一个经过实拍验证的主场景 → 自动分析并有手动兜底 → 长按呼吸 → 10 秒短片 → 本地保存/回看/下载。提供一件真实来源明确的 Tripo 资产，并验证它实际参与最终录制画面。失败时明确提示并允许继续拍摄或保存图片。

**有条件加入：** 楼宇/天空两个效果、三件统一风格资产、原生分享入口。每个效果单独过素材验收；单一主场景是保底范围，三场景版是目标范围。

**后续迭代：** 用户在线 Tripo 生成、Decart 实时视频、World Labs 片尾、硬件灯、空间 AR、账号/云作品库/社区。首版保留现有相关代码，普通用户界面收起实验入口。

## 5. 开发排期与依赖

估算假设：1 名全栈开发主力，美术与测试兼职配合；两台目标手机可用；素材授权和一个 Tripo 资产能及时提供。以下是工作量估算，不是已经承诺的交付日期。建议 12–15 个工作日，额外预留约 20% 联调缓冲。

| 阶段 | 工作量 | 具体任务 | 交付与放行条件 |
|---|---:|---|---|
| P0 基线与实拍样本 | 1–2 天 | 固定启动方式；采集 30 段树/楼/天/未知场景素材，覆盖白天、弱光、慢移、转场；留出 10 段不参与调参 | 素材索引含授权、设备、场景、预期区域；记录现状视频和耗时 |
| P1 拍摄与导出闭环 | 2–3 天 | 真机相机权限；输入切换；前后台恢复；录制/异常清理；作品保存；横竖屏；明确导出格式和图片降级 | iPhone Safari、Android Chrome 各完成录制→重开页面→回看→导出；目标分享端可播放 |
| P2 真实场景效果 | 3 天 | 测语义模型首载/推理；固定依赖和权重来源；记录蒙版时效；处理边缘、迟到结果和转场；提供手动场景与弱识别提示 | 树冠先过关；保留集中的可用率达到下述目标；不通过则缩小支持场景或改导入后处理 |
| P3 Tripo 资产落地 | 2 天 | 一件真实资产先打通导入→预览→合成→导出；记录来源；控制体积和材质；增加场景适用规则 | 同一件资产在两台手机可加载和录制；不兼容时显式报错；之后才制作另外两件 |
| P4 体验收敛与小测 | 2 天 | 主界面收敛为拍摄/作品；实验入口分离；首次提示；5–8 人无引导体验；记录完成和复拍 | 产出问题清单、修复优先级及实际用户指标 |
| P5 回归与候选版本 | 2–3 天 | 修复阻断问题；执行自动与真机回归；准备受控 HTTPS 测试入口、运行说明和已知限制 | 可复现构建、测试记录、设备矩阵和一段完整真实操作录像 |

关键路径：P0 → P1/P2 → P3 → P4 → P5。美术可以在 P1/P2 期间准备资产，但格式约束须先确认。不要在未知设备性能前投入三件高复杂度模型。

## 6. 建议验收标准

以下是待采用的目标，不是本次测量结果。P0 后根据实际设备调整并锁定。

- **闭环：** 每台目标手机连续 10 次录制均能保存、回看和导出；文件时长、画面比例正确，不能出现黑屏文件被当作成功。
- **性能：** 先以 720p 为基准，30 秒连续预览中位帧率 ≥24 FPS；记录低分位帧率、推理耗时和蒙版年龄；长按视觉响应目标 ≤150 ms。渲染 FPS 与语义更新频率分别报告。
- **稳定：** 10 次输入切换、5 次后台恢复无遗留相机占用或持续报错；连续使用 5 分钟无崩溃，记录发热及降速。
- **场景效果：** 留出集至少 80% 片段在停留/慢移时可用；“可用”定义为主体区域持续正确、无明显特效跳变、没有持续覆盖人物。标注失败类型，不能把规则阈值当识别置信度。快速移动和弱光失败应提示。
- **资产：** 真实模型来源可追溯；预览、合成、录制三个环节全部通过；不把模型查看器截图当最终成片验收。
- **产品：** 5–8 名目标体验者中 ≥80% 无开发者指导完成第一段短片，≥50% 主动拍第二个地点；小样本仅用于方向决策，不推断市场规模。
- **边界：** 默认本机处理；若后续开启云视频，单独说明画面发送、停止语义和费用；demo 与真实输出保留来源标记。

## 7. 工程策略与上线前补项

保留原生 JS + Node + SQLite 的单体结构，先修闭环，不为 MVP 预先换框架或拆服务。将新加的录制、资产和提交状态逻辑放入相应模块，避免继续堆到 `app.js`。

若开放在线付费生成，先持久化前端待确认请求及幂等键，页面重开后对账；保留不确定提交的人工核对机制。公开多人服务需要独立评估用户身份、任务隔离、用户级额度、数据留存和备份，当前共享管理令牌不能当作完整用户体系。

云提供商适配仅按当前源码评估，没有在本次核对最新官方 API 或价格。开始真实联调前，再核对官方接口、账号权限、SDK 版本、模型输出和预算；对应真实调用需有明确授权。优先只打通 Tripo，Decart 与 World Labs 不占主路径排期。
