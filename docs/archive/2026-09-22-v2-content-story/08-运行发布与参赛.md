# 08 运行、发布与参赛

## 1. 当前可执行命令

开发目录：`Breathe-City-All-In-One/01-project/breathe-city/`。从项目根目录执行：

```bash
cd Breathe-City-All-In-One/01-project/breathe-city
npm run verify
python3 tests/runtime_smoke.py
npm start
```

默认本机 http://localhost:3000 ，Node.js 22.16+。`verify` 包含语法、Node 测试、构建；runtime smoke 使用临时目录和本地模拟任务，不调用付费服务。源码与构建产物是不同入口，改源码后再构建分发版。

当前原型的 Docker/CI 文件存在但本次未验证镜像或远端流水线；这些命令不代表新故事功能已经实现。

## 3. 发布前准备

1. 记录版本与源码状态，确认新功能验收；保留原始 ZIP 和基线。
2. 受控 HTTPS 地址、正确 Origin、私有媒体卷、邀请会话、提供商预算和关闭开关到位。
3. 增加运行时 readiness：数据库可写、私有盘可用、必要迁移完成；liveness 单独判断进程。原有 health 的 200 不证明这些条件。
4. 备份 SQLite 与媒体清单，实际试一次恢复；WAL 模式使用数据库备份机制或停止写入后完整备份，不能只复制正在写的主库文件。
5. 发布候选版本，执行一次真实手机闭环；云入口先只对测试会话开放，验收后才扩大。
6. 保存发布标识、配置版本（去密钥）、设备证据、回退版本和责任人。

本次只准备文档，没有公开部署、发送邀请或提交比赛。

## 4. 运行观测与成本

记录请求 ID、内部 jobId、脱敏 providerId、模板/模型版本、状态转换、各阶段耗时、已知/预留成本、文件大小与错误码。主看成功生成率、用户接受率、导出成功率、重复提交数、未知成本和磁盘占用。

供应商计费与本地账目定期核对，异常时关闭新生成，保留已有任务查询。磁盘阈值触发停止新上传，不能覆盖旧作品以维持“正常”。

结果失效显示明确状态。为演示准备授权的历史样例，标明预先生成与制作时间；断网时可以体验本地故事，不能把旧样例冒充刚刚生成。

## 5. 回退与清理

回退顺序：关闭新生成 → 等待/记录当前任务 → 备份 → 切换兼容旧数据库的新旧构建 → 健康与作品读取验证。保留新表的加法迁移优先，避免为回退直接删库。新增媒体不随构建删除。

清理遵循 04 的到期与引用规则。删除只针对当前会话自有内容，带 pending 状态直到存储实际完成；模板升级不改已有作品。设备浏览器数据清理会删除本地作品，UI 在保存时说明。

## 7. 提交包

| 材料 | 内容 | 验收 |
|---|---|---|
| 可体验 Demo | 手机 HTTPS 入口、明确邀请方式、示例与个人输入 | 新访客实际可进入并完成故事 |
| 操作录屏 | 输入→选对象→动作→互动→导出→回放 | 连续真实过程；等待段如加速需标记 |
| 视觉资产板 | 原图、选区、故事分镜、结果静帧 | 来源、授权与生成方式清楚 |
| 项目说明 | 用户问题、核心闭环、实现边界、团队分工 | 区分已实现与后续 AR |
| 技术证据 | 版本、设备矩阵、模型来源与任务证据 | 去除密钥和访客个人信息 |
| 已知限制 | 输入类型、设备、网络、云等待、数据期限 | 与实际体验一致 |

建议 90–120 秒演示结构（内部建议，非比赛时长规定）：前 15 秒介绍“让熟悉的地方活起来”；中间展示完整一次制作/互动；结尾播放导出视频，说明实际能力与后续路线。故事主题可以使用“送给疲惫城市的一次休息”，不宣称医学疗效。
